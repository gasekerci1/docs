# Agent Readiness Checklist

This checklist is evidence-based. Do not mark a gate complete unless the cited document exists and the review owner has accepted it.

## P0 Checklist

- [ ] Master orchestration plan exists with execution order and dependency map.
- [ ] User research plan exists and avoids vulnerable-user recruitment without approval.
- [ ] PRD v0.1 exists with product boundaries and release gates.
- [ ] Non-functional requirements exist with measurable acceptance criteria.
- [ ] Canonical data model exists, including memory lifecycle and deletion/embedding invalidation.
- [ ] Privacy and consent pack exists with data inventory, consent model, retention, export, and deletion policy.
- [ ] Legal claims review pack exists for qualified legal review.
- [ ] AI evaluation harness exists with golden, red-team, refusal, privacy, and deleted-memory tests.
- [ ] Security threat model exists with prompt injection and AI-provider risks.
- [ ] Crisis localisation policy exists with supported locales, fallback copy, and resource maintenance process.
- [ ] Accessibility QA plan exists with WCAG 2.2 AA checklist and test scripts.
- [ ] Prototype UX specification exists for the low-fidelity validation flow.
- [ ] Curriculum and question bank exists for Modules 0-2 with safety review notes.

## P1 Checklist

- [ ] Market validation report exists with demand experiments and go/no-go metrics.
- [ ] API contract exists as conceptual planning documentation only.
- [ ] Operations and support playbook exists.
- [ ] Analytics and event taxonomy exists with consent and minimisation rules.
- [ ] Testing strategy exists with release gates and defect severity rubric.

## Prototype Readiness Checklist

- [ ] Prototype scope is limited to validation and low-fidelity learning.
- [ ] Participant consent and withdrawal language is ready.
- [ ] Module 0 and Module 1 prototype flows are specified.
- [ ] AI draft confirmation, edit, and reject flows are specified.
- [ ] Skip and pause controls are included.
- [ ] Crisis fallback copy is present and reviewed for boundaries.
- [ ] Accessibility checks are defined.

## MVP Build Readiness Checklist

- [ ] All P0 documents exist and have evidence-backed acceptance.
- [ ] User research has produced target-segment and problem/solution evidence.
- [ ] Privacy/legal/security/safety review questions have qualified-owner responses.
- [ ] Data model, consent, deletion, and embedding invalidation rules are consistent.
- [ ] AI evaluation thresholds and human review process are accepted.
- [ ] Architecture is based on completed P0 inputs, not assumptions.

## Closed Beta Readiness Checklist

- [ ] MVP build has passed functional, accessibility, security, privacy, deletion, consent, AI, and crisis/safety test gates.
- [ ] Support, incident, export, deletion, and consent revocation workflows are operationally assigned.
- [ ] Analytics is privacy-preserving and consent-aware.
- [ ] AI incident response and regression testing are defined.
- [ ] Legal, privacy, security, and safety owners have reviewed beta boundaries.

## Production Readiness Checklist

- [ ] Closed beta evidence supports production launch.
- [ ] Qualified legal/privacy/security reviews are complete.
- [ ] Monitoring, audit logging, backup/restore, incident response, and support coverage are production-ready.
- [ ] Crisis resources and localisation maintenance have accountable owners.
- [ ] The Integration Agent has confirmed P0 and P1 closure with evidence.

## Evidence Required For Each Gate

- Document path and version.
- Review owner.
- Decision date.
- Open issues and severity.
- Evidence source, such as interview synthesis, review notes, test results, or signed-off checklist.
- Explicit go/no-go decision.
