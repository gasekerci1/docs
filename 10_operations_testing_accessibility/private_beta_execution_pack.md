# Private Beta Execution Pack

## 1. Purpose

This pack operationalises the approved limited trusted private beta only. It does not approve public MVP/build, production readiness, public launch, commercial release, archive/delete/move cleanup, legal/privacy/security/accessibility compliance, broad AI use, multimodal data processing, wearables/passive monitoring, vector stores, or automated tool actions with live user data.

## 2. Current Approval Status

| Area | Status | Notes |
|---|---|---|
| Limited trusted private beta | GO | Trusted invited testers only, within approved consent and stop criteria. |
| Public MVP/build | NO-GO | No public build or public MVP approval. |
| Production readiness | NO-GO | Production evidence and approval remain missing. |
| Public launch/commercial release | NO-GO | No launch, marketing, paid release, or commercial readiness approval. |
| Compliance claims | NO-GO | No legal, privacy, security, regulatory, medical, or WCAG compliance claims. |
| Archive/delete/move cleanup | NO-GO | Cleanup requires separate exact file/destination approval. |
| Narrow OpenAI text use | GO within approved beta scope only | Text-only beta use under approved provider, consent, minimisation, retention, and deletion rules. |
| Vector/files/images/audio/video | NO-GO unless separately approved | Do not process these with live beta data under this pack. |
| Wearables/passive monitoring | NO-GO unless separately approved | No passive monitoring, phone signals, health/wearable data, or routine detection. |
| Support Circle | Opt-in planning/beta-limited only, not crisis response | No automatic alerts; no emergency escalation. |

## 3. Beta Entry Conditions

- [ ] Participant is trusted and invited.
- [ ] Participant received consent notice.
- [ ] Participant acknowledged consent.
- [ ] Participant understands product is pre-MVP and non-clinical.
- [ ] Participant understands deletion/export/withdrawal rights.
- [ ] Participant understands AI limits.
- [ ] Participant understands not to use the product for emergencies.
- [ ] Participant understands no medical/legal/financial/therapy advice is provided.

## 4. Beta Scope

Allowed:

- Text-only onboarding/reflection flows.
- Narrow AI text responses within approved provider scope.
- Manual feedback collection.
- Minimal safety classification logging.
- Consented support-circle planning or opt-in test only.

Not allowed:

- Public users.
- Public launch.
- Paid/commercial release.
- File upload.
- Image upload.
- Audio upload.
- Video upload.
- Vector stores/retrieval unless separately approved.
- Wearable/phone passive monitoring.
- Crisis monitoring or emergency response.
- Therapy/medical/legal/financial advice.
- Compliance claims.

## 5. Operating Rules

- Keep tester count limited.
- Keep logs minimal.
- Do not store sensitive free text in analytics.
- Do not use crisis text in memory or analytics.
- Do not reuse beta data for production without renewed consent.
- Honour withdrawal/deletion/export requests.
- Stop beta if stop criteria are triggered.
- Use only approved text-only AI flows; do not send files, images, audio, video, wearable, passive-monitoring, or unapproved vector data to any provider.
- Treat AI outputs as drafts requiring tester review.

## 6. Daily Beta Operator Checklist

- [ ] Confirm all active testers are listed by participant ID only.
- [ ] Confirm each active tester has consent acknowledged.
- [ ] Review new issues and classify severity.
- [ ] Review stop criteria checklist.
- [ ] Confirm no prohibited data category was collected.
- [ ] Confirm analytics contain no sensitive free text or crisis text.
- [ ] Confirm AI use stayed text-only and within approved scope.
- [ ] Confirm deletion/export/withdrawal requests are acknowledged and tracked.
- [ ] Escalate privacy, safety, security, consent, or AI-scope issues to the named owner.
- [ ] Record only minimal operational notes.

## 7. End-of-Beta Checklist

- [ ] Export requests handled.
- [ ] Deletion requests handled.
- [ ] Withdrawal requests handled.
- [ ] Unresolved incidents reviewed.
- [ ] Feedback summarised.
- [ ] Assumptions register updated.

- [ ] Beta data deleted or anonymised under approved workflow.
- [ ] No public readiness claims made.
- [ ] No production reuse without renewed consent.
