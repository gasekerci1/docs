# MVP Testing Strategy

Current status: planning-only MVP testing strategy.

This document does not approve public MVP build, private beta, production readiness, public launch, implementation, or compliance claims. No tests described here have been run unless a separate completed evidence record says so.

## Purpose

This strategy defines what a future public MVP test programme would need to evaluate before public MVP/build approval could be considered.

## Test Areas

| Test area | What to evaluate | Current status |
|---|---|---|
| Onboarding comprehension | Users understand BecomingOS is educational, non-clinical, pre-MVP/planning where applicable, and user-controlled. | Not run |
| Consent comprehension | Users understand data categories, optionality, retention, deletion, access/export, withdrawal, AI provider disclosure, and no production reuse. | Not run |
| Memory confirmation clarity | Users understand draft, confirm, edit, reject, delete, expired, archived, and consent-withdrawn memory states. | Not run |
| Today Directive usefulness | Users understand and can evaluate one practical next action and its rationale. | Not run |
| If-then plan builder | Users can create cue-linked action plans and fallbacks without confusion. | Not run |
| Bad Day Mode | Reduced plans feel supportive, non-shaming, and non-clinical. | Not run |
| Support Circle comfort | Users understand opt-in permissions, sharing limits, revocation, expiry, and no emergency monitoring. | Not run |
| AI explanation/citation | AI recommendations cite or explain confirmed user context and remain drafts. | Not run |
| Privacy comfort | Users understand and feel control over optional data categories and sensitive inputs. | Not run |
| Safety boundary comprehension | Users understand BecomingOS is not therapy, diagnosis, treatment, crisis intervention, emergency monitoring, or professional advice. | Not run |
| Accessibility | MVP-facing flows meet owner-approved accessibility baseline and are usable by target participants. | Not run |

## Evidence Required

Future MVP testing evidence should include:

- Test protocol and participant criteria.
- Consent and privacy review.
- Scripts or task guides.
- Findings summary.
- Issues and severity.
- Stop/pause events, if any, without sensitive free text.
- Accessibility QA evidence.
- Owner decision on whether findings satisfy public MVP/build gates.

## Boundaries

Testing evidence must not be used to claim clinical efficacy, guaranteed outcomes, legal/privacy/security/accessibility compliance, production readiness, or public launch readiness unless separate owner-approved evidence exists.
