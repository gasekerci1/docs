# Canonical Rewrite Instructions

Use these instructions for future canonical documentation work.

## Source Priority

Use `docs/02_product/becomingos_product_specification.docx` first. It is the current highest-priority product source of truth.

Older documents are supporting evidence. Use them for traceability, background, and unresolved questions, but do not let them override the source-of-truth specification.

## Canonical Structure

Use the repository root as the canonical documentation structure.

Do not use nested `docs/docs` structures as a source of truth. Nested `docs/` content may be evidence or historical work, but root-level canonical documents should govern future documentation unless the owner explicitly changes this decision.

## Preservation And Traceability

Preserve all originals until traceability is complete.

Do not delete, archive, move, or silently remove source material. When canonical documents replace older content, record what source documents informed the replacement and what conflicts were resolved.

## Stage And Beta Boundary

BecomingOS is pre-MVP. A limited private beta may be planned only under documented safeguards.

Private beta does not equal public MVP approval, public build approval, production readiness, commercial launch, or approval to reuse beta data in production.
