# Repository Audit - 2026-05-24

Scope: stabilisation and hygiene review for `personal-alpha-max-memory`.

## Summary

The application is a compact Next.js App Router project with TypeScript, Supabase, OpenAI, and Tailwind. The repository also contains a large documentation corpus with many duplicated `.docx` source artifacts.

No functional application code was removed or rewritten during this pass.

## Findings

### Duplicate Files

- Many byte-identical `.docx` files exist across `docs/00_inbox/`, `docs/01-source-documents/originals/`, and categorized documentation folders.
- Examples include PRD, prototype UX, research plan, API contract, NFR, security threat model, accessibility QA, testing strategy, and several memory/model documents.
- Action taken: documented as a retention/taxonomy risk. No document content was removed because these may represent source/archive/categorized copies.

### Temporary Files and Editor Junk

- Tracked `.DS_Store` files were present at repository root and inside documentation folders.
- Local `.next/` build output was present.
- A local `tsconfig.tsbuildinfo` file was generated by type checking.
- Action taken: expanded `.gitignore`; removed tracked `.DS_Store` files from the repository; removed local generated artifacts.

### Build Artifacts

- `.next/` exists locally and is ignored.
- No `.next/` files are tracked by Git.

### Secrets

- Text scan found placeholder environment keys in `README.md` and bearer-token handling code in `lib/auth.ts`.
- No committed real OpenAI key, Supabase service role key, or populated `.env.local` file was found in text-searchable project files.
- Binary `.docx` files were not deeply unpacked for secret scanning.

### Gitignore Coverage

- Existing `.gitignore` covered `node_modules/`, `.next/`, `out/`, `.env*.local`, `.vercel/`, and npm debug logs.
- Action taken: added broader env, cache, coverage, TypeScript build info, editor, OS, and alternate package-manager log ignores.

### Env Example

- `.env.example` already existed and included the required Supabase, OpenAI, owner email, and app URL keys.
- Action taken: left keys intact and documented `.env.local` usage in `README.md`.

### Dead or Legacy Folders

- Empty legacy documentation folders exist under dash-named paths such as `docs/06-testing/`, `docs/07-technical/`, `docs/99-archive/`, `docs/00-index/`, and nested `docs/05-product-spec/*` and `docs/02-research/*`.
- Action taken: documented only. No folders were removed because docs taxonomy cleanup needs a retention decision.

### Next.js Structure

- Current app structure is valid for App Router: `app/layout.tsx`, `app/page.tsx`, and API routes under `app/api/**/route.ts`.
- No `pages/` conflict was found.

### TypeScript Config

- `tsconfig.json` is compatible with Next.js App Router and strict TypeScript.
- `incremental: true` can generate `tsconfig.tsbuildinfo`; this is now ignored.

### Dependency and Lockfile Consistency

- `package.json` pins Next, React, TypeScript, ESLint, Tailwind, Supabase, OpenAI, and related types.
- `package-lock.json` is present.
- The local shell did not expose `npm`, so a true `npm install` verification could not be completed in this environment.
- Installed `node_modules/` allowed direct CLI checks via local binaries and the bundled Node runtime.

## Changes Made

- Improved repository ignore rules.
- Added ESLint flat config so linting is non-interactive and compatible with the existing Next.js dependency stack.
- Added Prettier formatting config and ignore file.
- Added `typecheck`, `health`, and `clean` scripts.
- Expanded README setup and guardrail instructions.
- Added project structure documentation.
- Added this audit report.
- Added changelog entry for the hygiene pass.

## Unresolved Risks

- Documentation duplicates remain and need an explicit source-of-truth/retention policy before cleanup.
- Empty legacy documentation folders remain pending a docs taxonomy decision.
- `.docx` binaries were not unpacked for exhaustive secret scanning.
- `npm install` could not be executed because `npm` is not available in this shell.
- The repository is currently in a merge state with unrelated staged documentation changes, so hygiene changes should be committed separately after the merge state is resolved or carefully staged with path-specific commands.
