- Treat `01-source-documents/originals/` as the safest preserved source-evidence set where it contains an exact source copy.
- Treat categorized folders as merge inputs and subject maps, not independent evidence when their files are exact duplicates of inbox/source copies.
- Treat `07_analysis/` and `08_final_outputs/` as review/readiness evidence, not final authority, until Phase 2 contradiction review and owner approval.
- Treat top-level MVP/app audit Markdown as potentially outdated or out-of-scope for this documentation-only planning repository unless the owner explicitly confirms the personal-alpha app context belongs here.

## Risks

- Duplicate files may make the same claim appear more supported than it is.
- Readiness documents include phrases about MVP, closed beta, production readiness, and architecture that need contradiction review before any canonical status is chosen.
- Privacy/safety/legal documents cover overlapping but not identical scopes; consolidating without Phase 2 could silently drop boundaries or jurisdiction assumptions.
- AI memory/data documents repeat core policies across several files; lifecycle, confirmation, and storage rules must be reconciled before final wording.
- Folder structure duplication increases the chance that agents update the wrong copy.
