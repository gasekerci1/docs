# Proposed Final Document Set

Phase 3 structure proposal for `gasekerci1/docs`.

This document proposes structure only. It does not approve MVP build, production readiness, archiving, deletion, file moves, or final canonical rewriting.

## Recommended Structure

Use the requested nested `docs/` structure as the proposed final system. It is clearer than the current mixed root-level folder system because it separates source-control documents, owner decisions, canonical subject documents, prompts, and future archive destinations.

```text
docs/
  00_repository_control/
  01_owner_decisions/
  02_product/
  03_research_validation/
  04_curriculum_question_system/
  05_ai_memory_data/
  06_privacy_legal_safety/
  07_architecture_api/
  08_operations_testing_accessibility/
  09_brand_experience/
  10_agent_prompts/
  99_archive/
```

## Recommended Structure Summary

- Keep `docs/00_repository_control/` as the active control plane.
- Add `docs/01_owner_decisions/` before rewriting any canonical product documents.
- Treat `docs/02_product/` through `docs/09_brand_experience/` as future canonical subject areas.
- Treat `docs/10_agent_prompts/` as prompt infrastructure only.
- Treat `docs/99_archive/` as a proposed destination only; no files should be moved there until owner approval.

## Owner Decisions Needed

- Approve final nested `docs/` structure.
- Approve which source folder is the evidence baseline.
- Approve naming and stage vocabulary before final product docs are written.
- Approve whether personal-alpha app references remain in scope.
- Approve archive destinations before any move/archive action.
